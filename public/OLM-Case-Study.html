03
The problem

Power users were spending more time fighting the tool than solving losses.

OLM tracks lost opportunities in continuous production — yield, energy, catalyst, downtime. The existing interface had grown organically over multiple releases.

  • Insights were split across four tabs; location filters reset between them.
  • Event tables wrapped, scrolled horizontally and obscured key actions.
  • Root-cause flows lacked breadcrumbs, with no clear back path.
  • KPIs that mattered most were buried inside drilldowns.
04
Method

Audited every screen against Nielsen's ten usability heuristics.

01Visibility of system status
02Match between system and real world
03User control and freedom
04Consistency and standards
05Error prevention
06Recognition rather than recall
07Flexibility and efficiency of use
08Aesthetic and minimalist design
09Help users recover from errors
10Help and documentation

Tiles highlighted in red were the three principles most frequently violated across the audited pages.

Findings

Eighteen issues across four pages, clustered into four themes.

01 / Theme
Navigation & orientation
Home button lands on an interim "main page" instead of the dashboard. Breadcrumbs and a back path are missing inside drill-downs.
Consistency · System status
02 / Theme
Filter & selection state
Location filters reset every time the user switches tab. Date pickers are split from their labels and act independently.
System status · Recognition
03 / Theme
Information density
Loss-category visuals are crowded. Event tables scroll horizontally. Repeated titles make sections hard to parse at a glance.
Aesthetic · Minimalist
04 / Theme
Action discoverability
"Create event" sits where filters would be expected. Footers stack four buttons. Clickable event IDs read as plain text.

Audit · Landing page

The home icon doesn't take users home.

Before

Users land on a hub of four module tiles. The page they actually need — Insights — is two clicks away every session.

Recommendation
01Route the home action directly into the Insights dashboard.
02Demote the module tiles into a persistent left rail.
03Surface a "last visited" entry point for return users.
04Cut the orphan page that was creating the extra step entirely.
Heuristic violated
Consistency & standards
07
Audit · Insights dashboard

Four tabs, four resets, four times the work.

Before

Insights split across OLM Summary, OLM Analytics, OEE, OLM Event Analytics and Process Reliability — each with its own location filter.

Recommendation
01Lift location selection to a global, persistent header.
02Collapse the five tabs into one summary with progressive drill-down.
03Promote the five most-used KPIs to the top of the page.
04Replace overlapping titles with a single, scannable hierarchy.
Heuristic violated
Visibility of status · Aesthetic minimalism
08
Audit · Event management

The most-used screen had the least breathing room.

Before

Event lists rendered as one wide table. Reviewer/Approver state lived in inline links. "Create event" sat next to filter dropdowns.

Recommendation
01Add a KPI strip for Open, In review, Approved and Rejected events.
02Split Reviewer and Approver into named workflow tabs.
03Move "Create event" to a primary action slot in the header.
04Use a master-detail split so events open in context, not on a new page.
Heuristic violated
Consistency · Aesthetic minimalism

15
What I learned

Three things that stuck.

"A heuristic audit is only useful when it leads to a specific design decision — every issue I flagged came with a sketch attached."
01 · Audit with intent
A heuristic violation in isolation tells you nothing — pairing each with a sketch made the redesign decisions defensible.
02 · Density is a design choice
In industrial tooling, more data does not equal more value. Picking five KPIs forced clarity on what the user actually needs first.
03 · Sketch in the room
Hand-drawn frames moved stakeholder conversations from "what is this?" to "where does this go?" within a single session.
